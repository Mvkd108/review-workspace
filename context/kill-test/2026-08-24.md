## Merge-readiness claims

No incorrect merge-ready claim occurred. No unit was ever reported `ready`.

- Five units were `blocked` for dirty worktrees. Verified manually:
  `git status --porcelain` returned 52 (muesli), 70 (cloud-agents), 26
  (COMPUSEAGENT_NATIVE), 19 (DevIQ-main), 25 (review-workspace) changed paths —
  all > 0, matching the "worktree contains uncommitted changes" reason.
- Eleven muesli agent worktrees were `blocked` with "The branch conflicts with
  the configured base reference." Spot-checked
  `agent-a-l10-l11-inventory`: `git merge-tree --write-tree origin/main HEAD`
  exits 1 — a real conflict. The `merge-conflict` attention item was raised.
- Two units (habit-garden, stock-signal-scraper) reported `unknown` with "The
  branch has no commits ahead of the base reference." Verified: both branches
  are clean and not ahead of `master`. Accurate.
- Note: an earlier pass registered three `master`-only repos with an explicit
  `baseRef: "main"`, producing "The configured base reference does not resolve."
  Re-registering with an auto-detected base ref (blank Base ref, the registration
  default) resolved them. This is operator input, not a host defect — see P2-1.

## Risk reasons

- The twelve muesli agent branches all produced the same high-risk reason set
  (`change.destructive`, `change.sensitive`, `change.no-tests`, `change.large`,
  `change.broad`, `git.conflict` where conflicting) with the same weight. These
  corresponded to real deletions: for `agent-a-l10-l11-inventory`, manual
  `git diff --name-status` showed 11 deleted files (worker services, scripts,
  docs) and ~215 files under `windows-native`. Not false positives, but the
  identical ordering among sibling branches is uninformative — see P2-2.
- The numeric sort key (`risk.sortScore`) is present in the API but was never
  rendered by the web app (covered by the existing no-score-in-UI test).

- **P2-1** — Registering with an explicit base ref that does not exist on the
  branch yields "The configured base reference does not resolve." Expected
  behavior; the registration form's auto-detect (blank Base ref) avoids it.
  Consider a validation hint in the form.

  the queue, and recency breaks the tie. The reasons are real; the sameness
  makes the ordering among siblings uninformative. No change warranted yet;
  record during the remaining days whether this confuses prioritization.
- **P2-3** — `unknown` agent state on worktrees whose transcripts predate the
  24-hour discovery window. Correct by design (no signal ≠ idle), but the
  operator must not read "unknown" as "agent not working recently." Consider
  whether the queue should surface a gentler hint after a full day passes.
